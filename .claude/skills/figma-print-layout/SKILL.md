# Вёрстка печатных полос в Figma

Свод выстрадан на каталоге MITODERM (794×561px = A5 альбомный, 32 полосы × 3 языка).
Каждое правило здесь стоило сломанной полосы. Порядок шагов обязателен: почти все
провалы были от того, что шаг выполнялся раньше времени.

## Нулевое правило: что неприкосновенно

Уточнить у заказчика и зафиксировать ДО начала. В типовом случае:

- **Символы текста не меняются.** Ни сокращений, ни склеек, ни срезания пустых
  строк. Проверяется контрольными суммами (см. «Приёмка»).
- **Изображения не меняются** — ни файл, ни кроп, ни пропорции.
- **Ручные правки заказчика — канон.** Полоса, проходящая приёмку, не трогается
  вообще. Это защищает то, что он уже поправил сам.

Всё остальное — кегли, интерлиньяж, координаты, ширины боксов, свойства фреймов —
рабочий материал.

---

## Шаг 1. Снапшот. До любой правки

Выгрузить по каждому текстовому узлу: `id, x, y, w, h, textAutoResize,
textAlignHorizontal`, длину и хеш `characters`, посегментно `fontSize/lineHeight`.
Положить в репозиторий CSV-строками.

**Plugin API не имеет доступа к истории версий Figma.** Без снапшота откат
невозможен — только руками через UI, и только владельцем файла. Один раз этого
уже стоило потерянных ручных кеглей заказчика.

## Шаг 2. Метрики, которым можно верить

### `absoluteBoundingBox` врёт — не использовать для контроля

Он возвращает **обрезанную** рамку, если у предка включён `clipsContent`.
Проверка «сдвинулся ли узел» по нему даёт ложь, скрипт «дочиняет» несработавший
сдвиг, двигает предка — и утаскивает всех соседей. Так рождаются каскады.

### Координаты — по цепочке родителей

```js
const posY = (n, frame) => { let y = 0, z = n; while (z && z !== frame) { y += z.y; z = z.parent; } return y; };
const posX = (n, frame) => { let x = 0, z = n; while (z && z !== frame) { x += z.x; z = z.parent; } return x; };
```

Точно и не зависит от клиппинга. Высоту брать `node.height`, не из bounding box.

### Контроль результата — только по чернилам

```js
const r = node.absoluteRenderBounds;   // границы реально отрисованных глифов
```

- Порог пересечения **2px**. Габариты боксов шире букв, поэтому по ним порог
  приходится задирать до 20px — и настоящие наложения в 9px проскакивают.
- В контроле участвуют **все** текстовые узлы, включая бейджи, врезки и подписи.
  Любое исключение «это же фурнитура» рано или поздно спрячет дефект.
- **`absoluteRenderBounds === null` — текст не отрисовывается.** Обрезан или стоит
  вне полосы. Это дефект, даже если геометрия формально в порядке.
- Из теста «низ полосы» исключать только колонтитул и вордмарк — они по макету
  стоят на своих местах.

### Эффективная высота блока

Хвостовые пустые строки раздувают бокс, но не печатаются. Для потока считать:

```js
высота = node.height − (число хвостовых пустых строк × интерлиньяж)
```

На одном узле это возвращало 75px вёрстки без единой правки текста.

## Шаг 3. Разведка структуры. До первой правки

### Вложенные фреймы с auto-layout

```js
frame.layoutMode !== 'NONE'   // присвоение y дочернему узлу ИГНОРИРУЕТСЯ
frame.clipsContent === true   // не влезшее МОЛЧА обрезается и становится невидимым
```

Половина провалов на каталоге была здесь: проходы по таким полосам не работали,
но рапортовали успех.

**Такими фреймами управлять их же средствами, а не координатами детей:**

```js
frame.primaryAxisSizingMode = 'AUTO';   // высота по контенту, ничего не обрежется
frame.itemSpacing = <шаг>;              // ритм
frame.clipsContent = false;             // страховка
// позиционировать САМ фрейм, а не его содержимое
```

Внутри auto-layout наложения невозможны по построению. Это не обход, а правильный
инструмент: 17 из 18 таких полос встали чисто сразу после перехода на него.

### Переводные версии: `y` мастера брать нельзя

Перевод длиннее невокализованного иврита на 40–60%, английский длиннее русского.
Координаты мастера рассчитаны под высоту блока на языке оригинала. Сброс геометрии
«как в мастере» **воспроизводит** наложения, а не лечит их.

Из мастера берётся только **`x` и порядок чтения**. `y` пересчитывается всегда.

## Шаг 4. Типографика

### Шкала

Семь-девять круглых ступеней на всё издание, больше ничего. Пример каталога:
`8 · 10 · 12 · 14 · 16 · 20 · 30 · 41` плюс фурнитура (вордмарк, обложка).
Дробные кегли (9.8, 11.3) — признак автоподгонки коэффициентами; это брак,
издание с 31 разным кеглем не читается как одно целое.

### Мера строки: 45–75 знаков

Диапазон Брингхёрста, оптимум ≈66. При 10pt Rubik это **≈330px**.
Полная ширина полосы 686px даёт ~137 знаков — **телу запрещена**, только титулам.
Блок тела шириной во всю полосу — всегда ошибка, даже если «влезает».

### Базовая сетка

Шаг сетки = интерлиньяжу тела (10/15 → шаг 15). Верх текстового блока садится на
линию. Титулы, пакшоты и фурнитуру на сетку не сажают.

Оговорка: снап стоит ~7px на блок. На плотных полосах с десятком блоков это 90px
впустую — там сетка отключается и работают чистые отступы. Сетка это инструмент,
а не догма.

### Пробел до заголовка больше, чем после

Закон близости: заголовок примыкает к своему тексту, а не висит между двумя.
Ориентир: 16–22 до, 2–3 после.

### Кегль внутри абзаца

Инлайн-акцент набирается **тем же кеглем**, что тело. Выделение держится
начертанием и цветом. Тело 8pt с акцентами 12pt — скачок в полтора раза посреди
предложения, выглядит как сломанный макет.

### Заголовок не переносится

Заголовок, ушедший на вторую строку, сначала расширяется **в пределах своей
колонки** (не на всю полосу — иначе заедет в соседнюю), потом опускается на
ступень шкалы.

## Шаг 5. Подписи к объектам: поле → кегль → вписывание

Не «поставить по центру», а посчитать. Порядок обязателен.

1. **Поле подписи** = территория между серединами зазоров с соседними объектами,
   обрезанная полями полосы.
2. **Ширина бокса** — симметрично относительно СВОЕГО объекта, иначе подпись
   уедет от предмета:
   `2 × min(центр − левая граница, правая граница − центр) − 2×отбивка`
3. **Кегль один на весь ряд** — наибольшая ступень, при которой влезают ВСЕ.
   Подбор каждой отдельно даёт ряд из 12 и 10 вперемешку, это читается как брак.
4. **Одна горизонталь**, подписи прижаты к ней **низом** (если над объектами) или
   **верхом** (если под). Тогда зазор «текст↔предмет» одинаков у одно- и
   многострочных.
5. Подпись **никогда не ложится на предмет**.

Центрировать по **оптической** массе, а не по габаритам кропа: если в кадре есть
прозрачные поля, габаритный центр и видимый не совпадают.

Ограничение: при кропах разной высоты одна горизонталь и равный зазор у каждой
взаимоисключающи. Приоритет у горизонтали — разнобой по высоте заметнее.

## Шаг 6. Поток: порядок приёмов

Для каждой грязной полосы, до первого «влезло»:

| # | Приём | Резерв |
|---|---|---|
| 1 | Эффективная высота без хвостовых пустых строк | до 75px на блок |
| 2 | Узкие блоки расширить до меры колонки | блок 102px в колонке 400px давал 144px высоты вместо 36 |
| 3 | Колонки из мастера, ширина по мере строки | приводит строку к норме |
| 4 | Поток: `y` пересчитывается, `x` и порядок из мастера | снимает наложения |
| 5 | Балансировка колонок по объёму | до 200px на полосах с разбегом |
| 6 | Сжатие зазоров до минимума | 10–20px |
| 7 | Ступень кегля вниз (12→10, 10→8) | ~36% высоты блока |
| 8 | **Не влезло → стоп.** Точный дефицит в отчёт | — |

После понижения кегля **обязательно пробовать обратный подъём**: часть полос
после перекладки вмещает прежний кегль, и оставлять их мелкими незачем.

### Запрещено

- **Обход препятствий потоком.** Три попытки «столкнуть текст ниже картинки»
  ломали канон-полосы: подписи уезжали под свои же пакшоты. Поток не обходит
  препятствия — пересечения ловит контроль, правит рука.
- **Глобальный решатель на все полосы сразу.** Одна ошибка эвристики множится
  на 64 фрейма. Полоса за полосой, с рендером после каждой.
- **Запуск потока поверх результата предыдущего потока.** Он не идемпотентен:
  первая строка колонки якорится по текущему `y`, сдвиг копится. Перед каждым
  прогоном — восстановление из снапшота.

## Шаг 7. Приёмка

1. **Символы**: хеши `characters` всех узлов совпадают со снапшотом. Расхождений 0.
2. **Чернила**: 0 пересечений с порогом 2px по всем узлам; ни одного
   `absoluteRenderBounds === null`.
3. **Поля**: ничего за `x` полей; ничего ниже линии колонтитула.
4. **Шкала**: только разрешённые ступени, без дробных.
5. **Краска тела**: один цвет на всё издание.
6. **Контраст**: у каждого текста считать отношение яркостей с подложкой, которая
   под ним реально нарисована (последняя залитая фигура ниже по порядку
   отрисовки, иначе — фон фрейма). Ниже 2.5 — дефект. Этой проверки не было, и
   она пропустила белый текст, уехавший с тёмной панели на кремовый фон:
   геометрия в порядке, наложений нет, текста не видно.
7. **Текст под позже нарисованной заливкой.** Контроль текст↔текст этого
   не ловит никогда. Проверять **не только картинки**: плашка, карточка, бейдж,
   панель — любой узел с непрозрачной заливкой. Отбор по имени («IMG», «Logo»)
   пропускает ровно то, что чаще всего и наезжает: у меня плашка схемы с именем
   `card` легла на строку спецификации, и прогон сказал «чисто».
   Узел перекрывает, только если нарисован **позже** текста — сравнивать
   индексы в порядке обхода, не только рамки. Считать **в абсолютных
   координатах**: пересчёт в систему фрейма даёт ложные срабатывания.
   У пакшотов прозрачный фон, поэтому габарит шире видимых пикселей — процент
   перекрытия это только повод посмотреть, а не приговор.
   Точный тест на «не видно вообще»: скрыть текст, заново экспортировать фрейм,
   сравнить хеш байтов. Совпал — текст не отрисовывается ни на пиксель.
8. **Начертания**: только разрешённые изданием. Любое другое — брак, даже если
   оно есть в гарнитуре.
9. **Чужая правка — не дефект.** Прежде чем назвать узел дефектным, сверить его
   с последним снимком состояния. Разошёлся, а ты его не трогал — это правка
   заказчика: она идёт в «принятые отклонения», и **предлагать её исправить
   нельзя**, даже мягко. Человек сделал это сознательно; предложение вернуть
   «как по правилам» заставляет его отвечать одно и то же на каждом проходе.
   Держать такой список поимённо, иначе контроль будет докладывать об одном
   и том же вечно, а однажды ты это «починишь» по инерции.
10. **Светлый текст — целиком на своей тёмной подложке.** Мало того, что
    контраст сошёлся: проверять, что бокс текста **не свисает** с плашки.
    Колонтитул, наполовину съехавший с тёмной панели на кремовый фон, проходит
    и контраст (считается по центру), и наложения, и поля — а в печати половина
    строки исчезает. Сравнивать габариты текста с габаритами подложки, а не точку.
11. **Верхнеуровневые узлы на экспортной странице.** На странице сборки не должно
    быть ничего, кроме самих фреймов. Узел-сосед виден на экране и не попадает
    в PDF фрейма: на макете одно, в печати другое.
12. **Рендер каждой изменённой полосы глазами.** Численной проверки мало — она
   дважды рапортовала «чисто» на полосах, где текст стоял в столбик по букве
   и где два узла вообще не отрисовывались.
7. Экспорт — отдельный шаг со своими проверками, см. ниже.

## Шаг 8. Экспорт: четыре дефекта, невидимых на канвасе

Полоса может быть безупречной, а издание всё равно уйдёт в печать битым.

### Сборочная страница из клонов — источник расхождений

Клон не связан с оригиналом и после любой правки устаревает **молча**.

**Правильно: экспортная страница держит сами полосы, а не копии.** Тогда полоса
и экспортная единица — один объект, расходиться нечему. Клоны терпимы только
если оригиналы лежат на отдельных страницах по одной полосе. Тогда перед каждой
печатью — сверка сигнатур каждой пары: все `characters` + габариты +
`imageHash/scaleMode`. Отчитываться только фактическим N/N.

### `exportSettings` только на фреймах верхнего уровня

Настройка экспорта, случайно попавшая на вложенный узел, добавляет его в выдачу
отдельным файлом. В интерфейсе этого не видно. Инвариант: **ровно одна настройка
на каждом из N фреймов, у всех потомков — пусто.** Проверяется обходом дерева.

### Порядок слоёв ≠ порядок на канвасе

`children[0]` — самый нижний слой, а панель слоёв читается сверху вниз, то есть
в обратном порядке массива: **первая полоса издания лежит в `children`
последней**. Два порядка задаются независимо и легко расходятся — страница
выглядит правильно, а многостраничный PDF собирается задом наперёд.

```js
const seq = page.children.map(c => no(c.name));
const layersOK = seq.every((v,i) => i === 0 || v === seq[i-1] - 1);        // N..1
const rows = page.children.map(c => ({ n: no(c.name), y: c.y })).sort((a,b) => a.y - b.y);
const canvasOK = rows.every((r,i) => i === 0 || r.n === rows[i-1].n + 1);  // 1..N
// разворот: for (let k = N-1; k >= 0; k--) page.appendChild(asc[k])
```

### Узлы верхнего уровня рядом с фреймами

Картинка, лежащая **соседом** фрейма, а не внутри него, на канвасе выглядит
частью полосы, но в PDF этого фрейма не попадёт. Инвариант: **на экспортной
странице нет ничего, кроме N фреймов полос.**

---

## Шаг 9. Бэкап — до прохода, не после

Plugin API не видит историю версий Figma (см. Шаг 1). Копия страницы, снятая
перед правками, — единственная страховка. У копии **снять `exportSettings` со
всех узлов**, иначе она всплывёт в выдаче при экспорте файла целиком.

Она же даёт лучшее доказательство безвредности прохода: поузловая сверка
«живая страница ↔ копия» по `characters` + `absoluteRenderBounds` показывает
численно, что не сдвинуто ничего. Это сильнее любого отчёта словами.

## Рецепты Plugin API

```js
// Шрифты — до ЛЮБОЙ мутации текста, включая resize и textAlignHorizontal
for (const s of node.getStyledTextSegments(['fontName'])) await figma.loadFontAsync(s.fontName);

// Один вызов setCurrentPageAsync на скрипт; чтение чужих страниц — через getNodeByIdAsync
// loadAllPagesAsync, setPluginData, createImageAsync — НЕ поддерживаются

// Смена ширины без сдвига видимого текста
const ink0 = node.absoluteRenderBounds;
node.textAutoResize = 'HEIGHT';
node.resize(w, node.height);
const ink1 = node.absoluteRenderBounds;
node.x += (node.textAlignHorizontal === 'CENTER')
  ? (ink0.x + ink0.width/2) - (ink1.x + ink1.width/2)
  : ink0.x - ink1.x;

// Подпись по содержимому
node.textAutoResize = 'WIDTH_AND_HEIGHT';
```

**Скрипт атомарен целиком: любое исключение откатывает ВЕСЬ прогон, включая
всё, что успело отработать до ошибки.** Проверено: запись текста на двух полосах
внешне прошла, упало позже — на потоке, — и в файле не оказалось ни одной из
записей. Отсюда два следствия. Первое: после падения ничего не «доделывается» —
перечитать узлы и повторить прогон целиком. Второе: длинный скрипт, который
правит десять полос, — это ставка «всё или ничего»; разбивать по полосе,
а рискованные мутации оборачивать в `try/catch` поузлово, чтобы сбой на одном
узле не уносил остальные.

```js
// Смена начертания — посегментно, с загрузкой И старого, И нового шрифта
for (const s of node.getStyledTextSegments(['fontName','fontSize'])) { /* план */ }
await figma.loadFontAsync({ family, style: target });
node.setRangeFontName(start, end, { family, style: target });

// Перенос узла в другой контейнер: бэкап координат ДО мутации.
// appendChild оставляет absoluteRenderBounds устаревшими до конца скрипта —
// поток, который читает их после переноса, разложит узлы не туда и не в том
// порядке. Сначала измерить ВСЕ узлы, затем расставлять по снятым числам.
const info = nodes.map(n => ({ n, delta: (n.absoluteRenderBounds.y - frameTop) - n.y,
                               h: n.absoluteRenderBounds.height }));
for (const it of info) { it.n.y = target - it.delta; target += it.h + gap; }

// Позиция строки внутри многострочного узла — клоном, а не арифметикой
const c = node.clone();
try { c.deleteCharacters(keep, c.characters.length); lineTop = node.y + c.height; }
finally { c.remove(); }
```

**Заказчик правит файл параллельно.** Сверять живую версию с копией, снятой
перед проходом, не только по геометрии, но и по **числу узлов на полосу**:
разошлось — значит узлы добавляли или делили, и снапшот больше не эталон
«текст не менялся». Такие полосы — его канон, их не трогать и не «чинить».
