## Постоянные решения заказчика
- База — приложение Codex `codex-site`; фильмы показывают процедуру по шагам; текст на экране — только HTML.
- **Один образ на страницу средства:** один косметолог и одна пациентка во всех кадрах и роликах страницы.
  EXO-NAD: опора — кадр K1 (задание `0af54a15-8b00-4543-977c-ff4940641e6d`) или K2 для крупных планов; опорный
  кадр прикладывать к каждому запросу. Косметолог тот же, что в фильме V-TECH; пациентка EXO-NAD новая: волосы
  убраны под белую махровую повязку, светлый трикотажный верх. Перчатки — белые. Утверждено 19/11.
- Упаковка — только по настоящему фото и рендеру; 3D-модель EXO-NAD неверна (флаконы).
- Ограничения EXO-NAD: без доз и времени, без игл и приборов, без мгновенного эффекта и вида «после».
- Телефон: фильм EXO-NAD делается отдельно в 9:16 (свои кадры и ролики), а не обрезкой — при обрезке одна из
  женщин выпадает из кадра. Опора вертикальных кадров — соответствующий кадр 16:9.
- Процедура EXO-NAD подтверждена заказчиком 19/11: пилинг наносят пальцами в перчатках; после нормализатора
  кожу протирают влажной салфеткой.
- Мелкие вопросы заказчику не задавать (19/11); решать самому и записывать сюда.
- Качество важнее веса: фильм V-TECH не жать до потери фактуры кожи.
- Набор V-TECH: 5 ампул сыворотки по 5 мл и 5 саше гелевой маски по 5 мл (`source-texts.md`, стр. 06; подтвердил
  заказчик). На рендере видно верхнее саше; текст крышки в кадре VK2 — как на рендере. Перчатки — на усмотрение
  исполнителя, оставлены белые.

## Как работать
- Сборка: `cd mitoderm-catalog/codex-site && corepack pnpm install --frozen-lockfile && corepack pnpm exec tsc --noEmit && corepack pnpm build`.
  Сервер: `setsid nohup corepack pnpm start > <временная папка>/server.log 2>&1 < /dev/null &`, порт 8787.
- Загрузка файла в хранилище: `media_upload` → `curl -X PUT -H "Content-Type: …" --data-binary @файл <ссылка>` →
  `media_confirm`. Ответ 520 бывает случайным — повторить.
- Ветка `claude/mitoderm-figma-catalog-74tbuw`; в коммитах только строка `Claude-Session: …`, без названий модели.
- Форму заявки на живом сайте не отправлять. Агентам не давать инструменты Higgsfield.
- Долгое — скриптом с пропуском готового; агент пишет заметки по ходу и коммитит каждую правку.
- Разрешения (`.claude/settings.json`): Higgsfield разрешён целиком, включая генерацию видео; запрос остаётся
  только на `mcp__atlascloud`.
- **Режим сессии.** В настройках сессии записан режим из списка рядом с полем ввода; каждый перезапуск возвращает
  её в него. Пока там «План», после перезапуска нужно окно подтверждения — заказчик переключает на «Авто».
  Перезапуски случаются после пауз от пяти минут (ожидание ответа в окне, долгий шаг без действий): работать
  короткими шагами и коммитить после каждого.
- Тестовая версия поднимается сама при старте облачной сессии (хук `SessionStart` в `.claude/settings.json`,
  если есть сборка `dist` и сервер не запущен); вручную проверено, на настоящем перезапуске — ещё нет.
- В основной оболочке не делать `cd` в подпапки и в папки агентов — меняется рабочая папка сессии; только
  `( cd … && … )`.
- Телефон проверять на 390×664 и 360×640 (сцена — `100svh`), а не только на 390×844.
- Ссылку загрузки (`media_upload`) в команду не переписывать: её берёт из журнала сессии скрипт
  `python3 mitoderm-catalog/state/tasks/put-upload.py <номер медиа>=<файл> …` (ссылку не печатает); затем `media_confirm`.
- Вопросы заказчику копить и задавать одним сообщением; работу не останавливать — брать вариант по умолчанию.
