# Карта страницы по числам — `qa/pagemap.cjs`

Один документ на все страницы: метод, запуск, легенда, проверки и пороги, калибровка, что числами не ловится.
Карты страниц и заметки по ним — `site/pagemap/` (`README.md` — дорожная карта 13 страниц, `<slug>.json`, `<slug>.md`).

## Зачем и как

Проверка 3D-страницы картинками в облаке без видеокарты стоила часов (1–2 с на кадр программного рендера). Карта страницы
строится по числам: three.js, который ничего не рисует (`qa/three-nodraw.mjs`, подставляется вместо `three.module.min.js`
с jsDelivr), на каждом кадре записывает для каждой видимой детали сцены мировую матрицу, прозрачность материала и вид
детали; проба (`PROBE` в `pagemap.cjs`) проецирует опорные точки геометрии (256 направлений) на холст и на каждом шаге
прокрутки в 10 px записывает: позицию истории, холст на экране, рамку каждой детали с прозрачностью, затухания сцены
(края, круглое затухание нырка, янтарный свет — униформами полноэкранных проходов), шапку, док-панель и нижнюю панель,
строки текста в виду (Range), нарисованную часть каждой картинки продукта, карточку набора, числа HD. Кадр `kit()`
(картинка карточки) записывается отдельно и заливает рамку набора, поэтому полёт в карточку считается как с настоящей
картинкой. Шаг устоялся за 2 кадра после `scrollTo` (событие прокрутки → слой движения → тик истории); при возврате холста
после карточек шагов проба ждёт ещё один нарисованный кадр. Проверки правил заказчика идут по этим числам (`analyse()`),
картинки — только там, куда указали числа (`--spot`), и финальный взгляд на 4 экрана.

Сверка инструмента с настоящим рисованием (SwiftShader): рамка из чисел совпадает с рамкой нарисованных пикселей в
пределах 1 px (12 шагов на 1440×900 и 390×844: открытие, S1–S4, прогоны 1, 2, 4, полёт; второй проверяющий — 196 кадров
без затуханий, расхождение ≤ 1.1 px). 2 кадра против 12 на 158 шагах — 0 расхождений (кроме времени качания пары).
Скорость: 15 режимов одной сборки за 2 мин (7–11 с на экран с 3D, 3–5 с без JS/WebGL) вместо часов.

## Запуск

```
cd mitoderm-catalog/site/proto
NODE_PATH=$(npm root -g) THREE=<…/three@0.160.0/build/three.module.min.js> \
node qa/pagemap.cjs <dir>/<slug>-live.html <dir> --out ../pagemap --raw <scratch>/raw \
  [--viewports all|key|<список>] [--keys <папка ключевых кадров>] [--build-cmd "<команда сборки>"] \
  [--looked <spot.json последнего --spot>] [--step 10] [--slug <slug>]
node qa/pagemap.cjs --from-raw <scratch>/raw --out ../pagemap [--looked …]        # проверки и карта заново по сохранённой пробе, секунды
node qa/pagemap.cjs --spot ../pagemap/<slug>.json <page> <dir> --out <scratch>     # картинки по флагам и цвету (настоящий three.js)
```

- `<page.html>` — сборка страницы (фрагмент body; оболочку документа добавляет хост), `<dir>` — папка, опубликованная с ней
  (`img/…`). Сборки и ключевые кадры живут вне репозитория (рабочая папка сессии); сборка опознаётся по md5 и ревизии
  файлов страницы (`build` в JSON: `rev`, `sourcesRev`, `cmd`, `keys`).
- three.js: `three@0.160.0` — `npm i --no-save three@0.160.0` в рабочей папке и `--three <file>` или `$THREE` (или
  `NODE_PATH`, где он установлен). Шрифт: `qa/fonts/Rubik[wght].ttf` (переменный Rubik 300–900, OFL, в репозитории; иначе
  `--fonts <dir>`, `$FONTDIR`). **Без шрифта или three.js инструмент останавливается**: подменный шрифт сдвигает каждую
  строку (на MITOTECH — 25 px высоты страницы, все удержания и прогоны ниже S5), и карта тихо становится другой. md5 шрифта,
  three.js и three-nodraw пишутся в `build.probe`.
- Экраны: `WxH[@dpr][t]` (t — касание, телефон или планшет), `nojs-…` (без JavaScript: скрипты страницы убраны), `nogl-…`
  (без WebGL: `--disable-3d-apis`). `all` — 11 экранов QA страницы и без JS / без WebGL на 1440x900 и 390x844 (15 режимов),
  `key` — 1280x720, 1440x900, 1920x1080, 390x844@3t.
- Выход: `<out>/<slug>.json` — карта (тонкая: один экран в строке, легенда внутри в `legend`; дорожка через 10 px и
  строки текста — только для ключевых экранов), `<out>/<slug>.md` — заметка (часть между `<!-- notes -->` и
  `<!-- /notes -->` прежней заметки сохраняется), `<out>/README.md` — дорожная карта (переписывается целиком, строки других
  страниц — из их JSON рядом). Дорожки и тексты всех экранов — `<raw>/<slug>.track.json.gz` (без `--raw`: `<tmp>/pagemap/`);
  сырые данные пробы — по одному `.json.gz` на экран в `<raw>`, для `--from-raw`.
- Одна тяжёлая работа браузера за раз (4 CPU). При перезапуске контейнера сырые данные на диске: `--from-raw` даёт карту
  за секунды, пробу повторить только для экранов, которых нет.

## Легенда JSON (коротко; полная — ключ `legend` в каждом JSON)

`page`, `build` (file, md5, rev, sourcesRev, sources, cmd, keys {dir, n, md5}, probe {font, three, nodraw}), `date`, `tool`
(script, doc, step, thresholds, probe), `timing`, `legend`, `texts` (id → [блок, тег, начало текста]; только блоки продукта),
`layout` (итог карты вёрстки L1–L8 из `<slug>.layout.json` рядом), `looked` (итог последнего `--spot`), `screens.<экран>`:
`mode` (desk / flow / still), `docH`, `blocks` (y блоков), `holds` ({p, y, parts: [{what, y, at, box}]} — удержание и что в
нём видно: 3d, cards, kc-live, kc-pic, none), `runs` ({k, y, px}), `flow` (телефон, по блокам: pose0 → run → pose1, frame),
`stepAside`, `landing`, `pictures` (nat — пиксели файла, page — место на странице, shown — где показана), `flags`,
`rules`, `design`, `count`, `errors`/`errs`; на ключевых экранах ещё `track` (RLE: p ×1000, box — рамка видимого продукта
до 2 px, canvas ×100), `texts` ([id, x0, y0, x1, y1(, sticky|fixed)]) и `pinned` ([id, y0, y1, x0, top, x1, bottom] —
где прижатая строка стоит на месте). p на компьютере — `__seq().pos` = `window.__mtP`; на телефоне и планшете — нарисованная
поза `sceneState.drawn` (там `window.__mtP` — позиция по странице).

## Правила заказчика → проверки по числам

| правило | флаг | как считается |
|---|---|---|
| продукт не режется прямой линией (край сцены, экрана) | CUT | рамка объекта (коробка, флакон) касается края видимой части сцены (≤ 3 px) или выходит за него, а затухания оставляют там > 0.25 → touch / hard; прямая мягкая полоса (старая виньетка, полоса края) гасит его > 25 % на ≥ 15 % размера и ≥ 12 px → soft-band; круглое затухание ≥ 0.75 — норма |
| не под шапкой, док-панелью, нижней панелью, телом карточки | UNDER_CHROME | 3D: пересечение рамки детали с панелью ≥ 2 px (компьютер — всегда; телефон/планшет — пока идёт прогон; там же выход за край экрана). Картинки продукта (нарисованная часть): под док-панелью и телом карточки на компьютере — флаг (во всех режимах, без JS и WebGL тоже); под шапкой и нижней панелью телефона картинка проходит с прокруткой страницы — в `design` как SCROLL (решение заказчика) |
| продукт не под текстом, текст не на нём | UNDER_TEXT | строки текста (Range) против рамок деталей 3D и нарисованной части картинок, ≥ 2×2 px |
| никогда два продукта сразу | TWO_PRODUCTS | 3D (видимые детали или янтарный свет) и каждая картинка продукта ниже шапки, ≥ 20 px и ≥ 1000 px²; карточки шагов — одна серия |
| ничего не просвечивает | GHOST | твёрдая деталь (коробка, этикетка, колпачок, пробка, порошок) с прозрачностью 0.05–0.95 без копии глубины, ≥ 400 px²: over — поверх другой детали, air — одна в воздухе; с копией глубины — FADE/solid (дизайн); деталь, которая приходит вместе с прозрачным узлом своего объекта (той же прозрачности, касаясь его) и за которой ничего нет, — FADE/clear-assembly (носик аппликатора): выводится из данных, без списка исключений |
| без скачков | POP | размер тела объекта за 30 px прокрутки × > 1.38 и за 60 px × > 1.75; смещение > 1.5 размера (без полёта холста); появление/исчезновение не за коробкой (закрыто < 30 %); уменьшение с угасанием в ближайшие 100 px — уход в темноту (дизайн) |
| без пустой сцены | EMPTY | компьютер: история идёт (p < 6), а продукта на экране нет ≥ 60 px прокрутки (короче — передача 3D ↔ картинка, дизайн); телефон: прогон идёт, сцена видна, продукта нет; dim: в нырке сильнейшее из света и продукта < 0.4 (и посередине между шагами) — тёмный кадр |
| прогону хватает прокрутки | RUN_SPAN (правило) | телефон < 300 px, компьютер < 500 px — идёт в `rules`, не в флаги: решение заказчика, не дефект кадра |
| компьютер: продукт слева, текст справа; телефон: заголовок → сцена → текст; ничего за краем | LAYOUT | строка текста левее середины продукта рядом с ним; картинка карточки шага правее её текста; порядок блоков на телефоне; горизонтальная прокрутка; строки и картинки за краем экрана |
| HD | HD | пиксели холста и картинок ≥ 0.95 × CSS × DPR (компьютер ≤ 2, телефон — DPR экрана) |

Видимым считается всё с прозрачностью ≥ 0.05 (`thresholds.op`): дорожка `track.box` и появления (POP/appear) идут от
этого порога, деталь при 1–2 % — ещё «ничего».

## Что числами не ловится → точечная проверка картинкой (`--spot`)

- Цвет и свет: чёрный кадр в нырке (теперь и числами: EMPTY/dim), светящаяся «панель» по краю сцены, янтарь стекла
  бустера, цвет раствора. `--spot` рисует настоящим three.js только нужные шаги: худший шаг флагов (≤ 3 на вид), свет
  нырка на 25/50/75 % (ярчайший 1 % холста ≥ 100 из 255; кромка холста 2 px не ярче страницы рядом + 12) и S3 (ΔE янтаря в
  точке пробы сцены к R15 #9b6630 ≤ 15). Калибровка картинкой: у fd91489 шаги EMPTY/dim дают ярчайший 1 % = 37–55 (FAIL,
  у проверяющего «max lum 48–55»); у текущей сборки на 4 ключевых экранах свет нырка 109–135 и кромка = странице ± 2 (PASS),
  янтарь ΔE 8 (PASS). Итог `--spot` попадает в карту через `--looked <spot.json>`.
- Не геометрия: нарисованные CSS-линии и плашки («только то, что есть»), кегль и сетка текста — проверка правил вёрстки
  `qa/layout-check.cjs` (L1–L8, `design-rules.md`); её итог карта берёт из `<slug>.layout.json` рядом.
- Что видно внутри детали (щелчки флаконов из-за края коробки), глубина резкости и темнота крупного плана — только
  картинкой.
- Сцены без хуков: страница без `window.__seq` (EXOCELL MASK) и движок кадров (V-TECH) пробе не видны — см. README.
