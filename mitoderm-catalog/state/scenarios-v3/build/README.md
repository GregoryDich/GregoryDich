# Сборка файла сценариев v3 (HE) — DOCX + PDF

Рабочая заметка (по-русски). Сам файл для заказчика — на иврите целиком.

## Одна команда

```bash
bash mitoderm-catalog/state/scenarios-v3/build/build.sh            # сборка + проверка, в рабочую папку
bash mitoderm-catalog/state/scenarios-v3/build/build.sh --publish  # то же + копия в site/xlsx-he/scenarios/, только если проверка прошла
```

Рабочая папка по умолчанию — `$W` = scratchpad сессии `.../scratchpad/scenarios-v3-build` (переопределяется: `W=/путь bash build.sh`).
Результат: `$W/out/final/MITODERM-video-scenarios-HE-v3.{docx,pdf}`; профиль LibreOffice — `$W/lo-profile`. ~45 с.
Нужны: `node` + глобальный `docx` (9.x; скрипт сам ставит `NODE_PATH=$(npm root -g)`), `soffice`, `pdftotext/pdfinfo/pdftoppm`, `python3`.

## Что делает build.sh

1. Снимок `../src/*.md` в `$W/out/src` — оба прохода и проверка читают одни и те же файлы, даже если авторы ещё коммитят.
2. Проход 1 (`build-docx.cjs --mark`): к каждой странице части и заголовку главы добавляется `QQMARKpgNN`;
   `post-docx.py` ставит RTL (`w:bidi`) в стили; LibreOffice → PDF; по тексту PDF находятся стартовые страницы → `pages.json`.
3. Проход 2 (`--pages pages.json`): те же файлы, в оглавлении (стр. 2) — номера страниц.
4. `verify.py` — проверки ниже; код выхода 1 при любой ошибке (с `--publish` копия тогда не делается).

Порядок печати — `PARTS` в начале `build-docx.cjs`: часть 1 «הקונספט וההפקה» (00, 01, 02), часть 2 «13 פרקי מוצר»
(EXO-NAD первым — образец), часть 3 «נספחים» (95, 97, 98, 99). `format-v3.md` не печатается. Нет файла — строка
`note: … skipped` в консоли, остальное собирается; часть без файлов не печатается.

Вёрстка: A4, поля 1000 DXA; обложка (заголовок/подзаголовок — `COVER_TITLE`/`COVER_SUB`), оглавление на стр. 2;
раздел `##`, в котором есть таблица из 8+ колонок (раскадровка), идёт на альбомных страницах, шрифт таблицы 7,5 pt;
ширины колонок считаются по тексту (не уже самого длинного слова до 16 знаков). Колонтитулы — как в v2.1.

## Проверки (verify.py)

- кириллица = 0 в XML docx и в тексте PDF;
- номера в оглавлении == стартовые страницы из прохода 1;
- для КАЖДОГО печатного исходника: каждое слово `.md` есть на страницах его главы (missing = 0);
- ни одного слова за полями печати (40 pt по бокам, 20 pt сверху/снизу), в т. ч. на альбомных страницах.

Вручную: `python3 -I verify.py <docx> <pdf> <pages.json> <docx.manifest.json>`.

## Ловушки LibreOffice, уже обойдённые в сборщике

- Повторяемая шапка таблицы одна внизу страницы + строки `cantSplit` → LO **терял строки таблицы**. Лечение: `keepNext` в шапке.
- Отдельный символ LRM перед `#0a0a0b` → LO рвал слово на конце строки. Теперь латинские `code`-фрагменты обёрнуты в LRI…PDI (U+2066/U+2069).
- Пути без дефисов LO рвал посреди имени файла → после каждого «/» в `code` стоит ZWSP (U+200B).
- `w:line=276` без `lineRule` LO читал как «точно 13,8 pt» → двухстрочный заголовок обложки налезал. Теперь `lineRule: auto`.
- Нумерованный список, продолженный после абзаца/подзаголовка, начинается с номера из исходника (5., 10., …).
- `\|` внутри ячейки таблицы печатается как «|».
