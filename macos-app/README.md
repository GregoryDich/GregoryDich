# 🐠 AquariumWallpaper — живые обои для macOS

Нативное приложение: рыбки плавают **на рабочем столе, за иконками** — как у того
приложения из App Store, но с нашим аквариумом. Это **значок в строке меню** (трей)
+ невидимое окно-обои на каждом мониторе. **Без меню паузы/настроек** — только
диагностика, тема аквариума, отзыв, пара переключателей и «Выход» (см. «Меню рыбки»).

- Цель: **MacBook M4 Pro, 4K**, Retina-чёткость.
- Оптимизация: 60 fps от сети; **30 fps от батареи, в режиме энергосбережения (Low Power Mode)
  и при перегреве** (`thermalState` serious/critical); **пауза при засыпании дисплея**;
  второй и следующие мониторы — 30 fps и 2 Мп. Бюджет пикселей холста: 3,7 Мп от сети, 2,4 Мп от
  батареи, **1,8 Мп в Low Power Mode и при перегреве** (на любом экране).
- Движок — наш `../aquarium/` (встраивается в .app), рыбы берутся из `fish/`.

## Сборка (Terminal, Xcode Command Line Tools должны стоять)

```bash
cd macos-app
chmod +x build.sh
./build.sh --run
```

Появится значок рыбки 🐟 в строке меню, аквариум станет фоном рабочего стола.
Если обои уже запущены, `--run` сам закроет старую копию.

Собирается универсальный файл (Apple Silicon + Intel) для macOS 13+ — та же версия, что
`LSMinimumSystemVersion` в `Info.plist`, на каком бы Mac ни собирали. Быстрее, только под
свой Mac: `ARCHS=arm64 ./build.sh`.

## Подпись вашим Apple Developer ID

```bash
# посмотреть доступные сертификаты:
security find-identity -v -p codesigning
# собрать и подписать:
./build.sh --sign "Developer ID Application: ВАШЕ ИМЯ (XXXXXXXXXX)"
```

Так Gatekeeper не будет ругаться на «неизвестного разработчика». Без подписи
первый запуск: **ПКМ по .app → «Открыть»**, либо *Системные настройки →
Конфиденциальность и безопасность → Открыть всё равно*.

## Меню рыбки
| Пункт | Что делает |
|---|---|
| **Показать FPS** | галочка (запоминается): HUD производительности поверх аквариума на всех экранах (виден, когда рабочий стол не закрыт окнами) — к/с, интервалы p50/p90/p95, JS-мс, буфер, бюджет, регулятор, видео. HUD — DOM-элемент, на холсте не рисуется |
| **Скопировать диагностику** | JSON в буфер обмена: `aquariumPerfSnapshot()` с каждого экрана + модель Mac и чип (`hw.model`, `machdep.cpu.brand_string`), ОЗУ, macOS, все экраны (размер, `backingScaleFactor`, `maximumFramesPerSecond`, главный ли; в `host.screens` — ID экрана и есть ли на нём аквариум: `shown`/`parked`/`none`), сеть/батарея, Low Power Mode, `thermalState`, версия, счётчики загрузок, сбоев и зависаний страницы, выбранная тема (`host.theme`; что на экране — `windows[].snapshot.theme`: `mode`, `target`, `k`), галочка «Задник слоями» (`host.vlayer`; с чем загружена страница — `windows[].vlayer`, что в работе — `windows[].snapshot.vlayer`). Вставить (⌘V) в письмо или чат |
| **Тест производительности (≈45 с)** | только с зажатой **⌥** при щелчке по рыбке. `aquariumPerfProbe()` на главном экране: 11 конфигураций по 4 с (как есть, 3,7 и 2,4 Мп, без каустики/лучей/виньетки, постер вместо видео, без рифа/света рыб/групп, последней — «как было»). Mac не трогать; по окончании — окно с итогами (к/с, p50/p90, JS-мс по каждой конфигурации), полный результат в буфере обмена. Перед тестом покажите рабочий стол (F11): пока аквариум закрыт окнами, WebKit его не рисует (тест тогда не запустится). Если стол закрыли или дисплей заснул — «прерван», в буфере то, что успели. Не запускается, пока открыт «Тест слоёв» |
| **Тест слоёв** | только с **⌥**: `aquarium/spike/layers.html` в обычном окне (CSS-смешивание над видео против холста, P1.8). Пока окно открыто, обои на паузе — не мешают замеру; пока идёт тест производительности, пункт недоступен. Клавиши страницы (1/2/3, E, D, T, H) работают сразу, ⌘W закрывает |
| **Задник слоями (тест)** | только с **⌥**; галочка (запоминается, `aq.vlayer`, по умолчанию выключено): задник движка слоями (P1.9/P1.7 — видео, затемнение, каустика и лучи CSS-слоями под/над прозрачным холстом; холст 6 Мп от сети / 3,7 от батареи, P1.11). Режим выбирается при загрузке страницы (`__AQ_BOOT.vlayer`), поэтому переключение **перезагружает аквариум на всех экранах** (и «припаркованных»; причина загрузки `vlayer` в `aq.pageLoads`), окна не пересоздаются. Пока идёт тест производительности, пункт недоступен (перезагрузка сорвала бы замер). Что на экране — `windows[].snapshot.vlayer` в диагностике и строка HUD; зонд сравнивает оба пути (конфигурация `vlayer`/`canvas`) |
| **Тема аквариума ▸** | подменю, галочка у выбранного (запоминается, `aq.theme`): **Как в системе** (`auto`, по умолчанию — по оформлению macOS: «Светлое» — день, «Тёмное» — ночь, «Автоматически» меняется само), **Всегда день** (`day`), **Всегда ночь** (`night`). Применяется сразу на всех экранах — плавный переход ≈ 3 с; после перезапуска или перезагрузки страница с первого кадра в выбранной теме (без перехода «день → ночь») |
| Написать отзыв… | окно обратной связи (ниже) |
| **Только на главном экране** | виден при 2+ мониторах; галочка (запоминается): аквариум только на экране со строкой меню, остальные окна закрываются |
| Запускать при входе | `SMAppService` (macOS 13+) |
| Выход | ⌘Q |

## Как это работает (коротко)
- `main.swift` — агент в строке меню (`.accessory`, без иконки в Dock).
- `WallpaperWindow.swift` — borderless-окно на уровне `desktopWindow` (выше
  картинки рабочего стола, ниже иконок), `canJoinAllSpaces` + `stationary`,
  `ignoresMouseEvents` (клики проходят к иконкам). Внутри — `WKWebView` с
  аквариумом в режиме обоев. До загрузки страницы (`WKUserScript`, document start) приложение
  передаёт `window.__WALLPAPER = true`, `window.__AQ_POWER` и
  `window.__AQ_BOOT = {power, hud, budget, screen: {id, w, h, scale, maxFps, main}, crashes, unresponsive, loadReason, appVersion, theme, vlayer}`
  (`w`/`h` — в точках; `budget` — `{mp, fps}` или `null`: на втором и следующих экранах `{mp: 2, fps: 30}`, в Low
  Power Mode и при перегреве `mp: 1.8` на любом экране, `null` — бюджет движка; `loadReason` — `launch` |
  `displayAdded` | `crashReload` | `retry` | `vlayer` (перезагрузка по переключателю «Задник слоями»); `crashes`/`unresponsive` — сколько всего было сбоев и зависаний; `theme` —
  `auto` | `day` | `night` из «Тема аквариума», движок выбирает тему до первого кадра (`?theme=` в адресе, для тестов,
  сильнее); `vlayer` — `true`/`false` из «Задник слоями (тест)», читается только при загрузке (`?vlayer=` в адресе
  сильнее); ключи только добавляются, старые страницы их не замечают). После загрузки: `aquariumSetPower('high'|'low'|'paused')` (только при
  смене), `aquariumSetBudget({mp, fps})` при смене роли экрана или Low Power Mode/перегрева (`{mp: null, fps: null}` —
  снова бюджет движка), `aquariumSetDebug(on)` для HUD, `aquariumSetTheme('auto'|'day'|'night')` — при выборе в меню
  (всем окнам, и «припаркованным») и после каждой загрузки (та же тема — ничего не меняется; выбранная во время
  загрузки — переход). Всё, что подставляется в JavaScript, кодируется как JSON
  (`PageScript.literal`), строки не склеиваются вручную.
- `AppDelegate.swift` — меню, по одному окну на экран (по `CGDirectDisplayID`), питание (IOPS, Low Power
  Mode, `thermalState`), сон дисплея. Смена экранов обрабатывается через **1,5 с** после последнего
  уведомления (macOS шлёт их пачкой, внешний монитор на миг пропадает). Окно ушедшего экрана
  **15 минут** держится скрытым и на паузе: монитор вышел из ожидания — та же страница, без перезагрузки.
- **Сбой страницы.** Процесс WebContent убит (память, сбой GPU-процесса) или страница не загрузилась →
  перезагрузка через 1 / 5 / 15 с, дальше раз в 10 минут, при пробуждении дисплея и при смене экранов
  (никогда не «чёрный навсегда» и без шторма перезагрузок). Причина берётся из приватного метода WebKit
  `_webView:webContentProcessDidTerminateWithReason:` (0 память, 1 CPU, 2 клиент, 3 сбой, 4 предел сбоев
  GPU-процесса) и пишется в `UserDefaults`: `aq.wc.total`, `aq.wc.log` (последние 20: время, экран,
  причина, секунд с загрузки, `unresponsiveSec` — если перед этим страница висела), `aq.pageLoads` (число загрузок
  по причинам) и `aq.pageLoads.log`.
- **Зависание страницы** (≈ «замерло, потом белый экран»). Два источника: приватные методы WebKit
  `_webViewWebProcessDidBecomeUnresponsive:` / `_webViewWebProcessDidBecomeResponsive:` (WebKit зовёт их, когда
  процесс страницы 3 с не отвечает на то, чего UI-процесс ждёт, — а ждёт он только загрузок и ввода, которого у обоев
  нет) и свой пульс приложения: раз в 10 с видимой работающей странице уходит `evaluateJavaScript("0")` (по одному
  за раз); нет ответа за 6 с — зависание с момента отправки (на скрытой странице пульс молчит, на `paused` — его
  таймер стоит: ни одного пробуждения за ночь сна дисплея; опоздавшая из-за App Nap проверка ждёт ещё секунду).
  Страницу убили, когда пинг ждал ответа ≥ 2 с, — тоже зависание (закрыто как `terminated`, `unresponsiveSec` в
  `aq.wc.log`). «Ответила» — только успешный ответ; ошибка вызова решается через оборот цикла (WebKit проваливает
  ожидающие вызовы гибнущего процесса в том же стеке, ДО сообщения о гибели, и с кодом 5, а не «процесс завершён»):
  гибель за это время — её вердикт, иначе — без вердикта; «responsive» от WebKit тоже засчитывается через оборот
  цикла (сбой в том же стеке закрывает эпизод как `terminated`). → `aq.unresponsive.total` и `aq.unresponsive.log`
  (последние 20: время начала, экран,
  секунд с загрузки, `source` — `webkit` | `heartbeat`, `end` — `responsive` | `terminated` | `closed` | `open`
  (приложение закрыли, пока висело), `durationSec`). В диагностике:
  `lifecycle.unresponsiveTotal`/`unresponsiveLog`, `windows[].unresponsiveThisRun` и, если страница висит прямо
  сейчас, `windows[].unresponsiveForSec` (снимок `snapshot` тогда — `{"error": "timeout"}`).
- `Lifecycle.swift` — журнал, настройки, счётчики; `LayersTestWindow.swift` — окно «Тест слоёв».

## Журнал и отладка
```bash
# что происходило (загрузки страниц с причиной, сбои, экраны, питание):
log show --last 3h --style compact --predicate 'subsystem == "com.gregorydich.aquariumwallpaper"'
log stream --predicate 'subsystem == "com.gregorydich.aquariumwallpaper"'      # вживую
# счётчики сбоев, зависаний и загрузок (aq.wc.*, aq.unresponsive.*, aq.pageLoads*):
defaults read com.gregorydich.aquariumwallpaper
# Safari ▸ Разработка ▸ <ваш Mac> ▸ страница обоев (macOS 13.3+; затем перезапустить приложение):
defaults write com.gregorydich.aquariumwallpaper inspectable -bool YES
```
Настройки: `aq.hud` («Показать FPS»), `aq.onlyMainScreen` («Только на главном экране»), `aq.theme` («Тема
аквариума»: `auto` | `day` | `night`; нет ключа — `auto`), `aq.vlayer` (⌥ «Задник слоями (тест)»; нет ключа —
выключено), `inspectable`.

**Проверить на Mac** (P1.1–P1.2; здесь нет компилятора — код проверен только по типам на заглушках):
⌥ при щелчке по рыбке показывает оба теста, без ⌥ их нет; галочка «Показать FPS» переживает перезапуск;
«Скопировать диагностику» → в JSON есть `chip`, `windows[].snapshot`, `lifecycle`; внешний монитор
выключить и включить в пределах 15 мин → в журнале «is back … no reload»; завершить в «Мониторинге
системы» процесс Web Content приложения → аквариум вернётся через ≈1 с, в `aq.wc.log` появится запись;
Low Power Mode → в журнале «power low (lowPowerMode)», в HUD «бюджет 1.8 Мп (app)», в диагностике
`windows[].budget` = `{"fps": null, "mp": 1.8}` (на втором экране `{"fps": 30, "mp": 1.8}`); выключить — снова
3,7 Мп (или 2,4 от батареи) через ≈3 с. Второй монитор: в HUD на нём «предел 30 к/с» с первого кадра.
«Тема аквариума ▸ Всегда ночь» при светлом оформлении → ночь на всех экранах за ≈3 с, галочка на «Всегда ночь»;
выйти и запустить снова → сразу ночь, без дня в первые секунды; «Как в системе» → снова по оформлению macOS;
в диагностике `host.theme`.
⌥ «Задник слоями (тест)» → аквариум на всех экранах перезагружается (≈1 с чёрного), в журнале «reload requested
(vlayer)» и «load display …: reason=vlayer … vlayer=true», галочка стоит и переживает перезапуск; в HUD строка
слоёв, в диагностике `host.vlayer: true`, `windows[].vlayer: true`, `windows[].snapshot.vlayer: true`,
`lifecycle.pageLoads.vlayer` растёт; ⌥-пункт недоступен, пока идёт тест производительности; выключить → снова
перезагрузка, `snapshot.vlayer: false`. Внешний монитор отключить, переключить режим, подключить в пределах
15 мин → «is back … no reload» и на нём уже новый режим (припаркованная страница перезагрузилась скрытой).

## Окно обратной связи («Написать отзыв…»)
Пункт меню рыбки после диагностики. Открывает обычное окно (не на обоях; обои по-прежнему
пропускают клики). В окне: тема («Ошибка», «Идея», «Хочу рыбку», «Другое»), текст
10–2000 знаков (единственное обязательное поле), необязательный e-mail, отдельная
галочка «группа первых пользователей» (опросы/новости — только по желанию, выключена,
доступна лишь с e-mail), снимок аквариума и диагностика (обе выключены; диагностика
включается сама для «Ошибки»; ровно тот JSON, что уйдёт, виден по ссылке «Показать,
что отправится ▸») и согласие — по умолчанию снято, без него «Отправить» не работает.
Отправка — кнопкой или ⌘↩; не чаще 5 раз за 10 минут; черновик сохраняется.

**Копия всегда остаётся на Mac:** `~/Library/Application Support/AquariumWallpaper/Feedback/<id>.json`
(+ `<id>.jpg`), права 0600, хранится 90 дней, не больше 100 отзывов. Дальше маршрут по ключам
`Info.plist` (читаются при открытии окна):

| Ключ | Сейчас | Что делает |
|---|---|---|
| `AQFeedbackEndpoint` | пусто | HTTPS-адрес сервера → POST JSON (`aq.feedback/1`). `http://` игнорируется. Нет сети / 429 / 5xx → «уйдёт автоматически»: повтор через 10 с после запуска и раз в час, до 5 попыток, 7 дней |
| `AQFeedbackEmail` | `support@tonamorph.com` | если сервера нет — открывается готовое письмо (`mailto:`); в подтверждении есть «Скопировать текст» (Почта без настроенного ящика, веб-почта); нет почтовой программы → буфер обмена |
| `AQPrivacyPolicyURL` | пусто | HTTPS-ссылка «Политика конфиденциальности» под согласием |

Оба пустые → текст копируется в буфер обмена с путём к копии. Адрес меняется одной
строкой в `Resources/Info.plist`. Что **никогда** не собирается: серийный номер, UUID,
имя пользователя/компьютера, IP, Wi-Fi, списки приложений и окон, пути, ID установки.
Снимок — только аквариум (`WKWebView.takeSnapshot`, без разрешения «Запись экрана»),
≤ 1600 px, ≤ 400 КБ. К схеме `aq.feedback/1` добавлено необязательное поле `marketing` —
только при галочке «группа первых пользователей», иначе ключа в JSON нет (такие отзывы проходят
схему v1 с `additionalProperties: false`). Серверу нужно принять это поле:
`{"type":"object","additionalProperties":false,"required":["optIn","version","at"],"properties":{"optIn":{"const":true},"version":{"type":"string","pattern":"^fb-marketing-[a-z]{2}-[0-9]+$"},"at":{"type":"string","format":"date-time"}}}`;
согласия на рассылку сервер хранит отдельно и выполняет отписку («отписаться» в ответ на письмо).

**Проверить на Mac** (здесь нет компилятора — код проверен только по типам на заглушках):
сборка `./build.sh`; ⌘C/⌘V в полях на русской раскладке и с Caps Lock; Почта без ящика →
«Скопировать текст»; видео-задник на снимке
(если чёрный — подпись «Снимок без видео-фона» и хук снимка в движке); тёмная тема;
два монитора (снимок — с главного).

Файлы: `Feedback.swift` (тексты, ключи, модель, хранилище, доставка, повтор),
`FeedbackWindow.swift` (окно, пункт меню), `Diagnostics.swift` (диагностика, снимок).

## Рыбы в высоком качестве
Аквариум уже работает с векторными рыбками. Чтобы заменить их на реалистичные:
положите прозрачные PNG в `../aquarium/fish/` (имена и промпты — в
`../aquarium/fish/PROMPTS.md`). Приложение подхватит их при следующем запуске.

## Если что-то не так
- **Обои поверх иконок / не видно** — поменяйте уровень окна в
  `WallpaperWindow.swift`: вместо `.desktopWindow` попробуйте
  `CGWindowLevelForKey(.desktopIconWindow) - 1`.
- **Несколько мониторов** — окно создаётся на каждый; при смене разрешения или
  расположения окно только меняет размер (без перезагрузки). Второй и следующие
  экраны идут с 30 fps и бюджетом 2 Мп; «Только на главном экране» оставляет один.
- **Аквариум «перезапускается», замирает, чёрный или белый экран** — «Скопировать диагностику» (лучше прямо
  во время зависания) и `log show …` из раздела «Журнал и отладка»: там видно, висела ли страница
  («WebContent unresponsive»), сколько, и была ли перезагрузка и почему.
