# WS1.0 coding instrument — Google Forms edition

Same instrument as `../ws1_survey.html`, delivered through Google Forms:
one fragment per page, valence asked only when relevance = Yes, order
randomised per coder, answers stored by Google. Coders get a normal Forms
link — nothing to install, drafts autosave for signed-in Google users.

Google Forms has no API for bulk building, so the form is generated by a
Google Apps Script that you paste and run once per coder.

## Files

| file | role |
|---|---|
| `build_form.template.gs` | Apps Script builder (tracked; no fragment text) |
| `make_gform_script.py` | fills the template with the 300 fragments -> `generated/build_form.gs` |
| `gforms_to_csv.py` | converts the Forms responses export into per-coder CSVs for `ws1_gate.py` |
| `generated/` | git-ignored output (contains verbatim caption text) |

## 1. Generate the script (once)

```bash
cd narrative-economics/code/ws1/gforms
python3 make_gform_script.py            # add --restore-sample if coding_sample.csv is missing
```

## 2. Build one form per coder

1. Open <https://script.google.com> → **New project** → delete the default
   code → paste the whole of `generated/build_form.gs` → save.
2. Set `CODER = 'Anna'` at the top → save.
3. **Run ▸ buildForm**. First run: allow the Forms/Drive permission, then
   click Run again.
4. Watch the **Execution log**. Apps Script caps a run at ~6 min, so the
   builder pauses itself and says *"Run buildForm again"* — run it again
   until the log prints **DONE** (2–4 runs; each resumes where it stopped).
5. DONE prints two links: **EDIT URL** (yours) and **RESPONDENT URL** — send
   the respondent link to that coder.
6. Second coder: change `CODER`, save, Run ▸ buildForm again.

`status()` shows progress + links; `resetProgress()` clears the build state
if you need to start over (move the old form to Trash yourself).

If the respondent link says the form is not accepting responses, open the
edit URL and click **Publish** (newer Forms require it; the script tries to
do this for you).

## 3. Collect and score

Form → **Responses** → ⋮ → **Download responses (.csv)**, then:

```bash
python3 gforms_to_csv.py responses_Anna.csv --sample ../coding_sample.csv
python3 gforms_to_csv.py responses_Gregory.csv --sample ../coding_sample.csv
python3 ../ws1_gate.py ws1_coded_Anna.csv ws1_coded_Gregory.csv ../fragments.csv
```

Gate: κ ≥ 0.70 on relevance and on valence (see `../CODEBOOK.md`).

## Known limits vs the HTML app

- **Back button** — Google Forms cannot hide it. Coders are asked not to use
  it; `ws1_survey.html` enforces no-return if that matters more than the
  Forms convenience.
- **Randomisation** — Forms cannot shuffle pages per respondent, so each
  coder gets their own form with its own fixed shuffle (seeded by the coder
  name — the same order that `ws1_survey.html` gives the same name).
- **Editor speed** — a 600-section form opens slowly in the editor. The
  respondent view (one page at a time) is fine.
- **Timing** — Forms records only the submission timestamp, not per-item
  time; the HTML app records seconds per fragment.
